# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Astro (static output), chosen by the user. `docs/` remains the GitHub Pages source: the
build writes the output into `docs/` and CI commits that directory back to `main`.

## Users

**Primary — developers already using DeepSeek Harness (dsh).** They arrive with an intent
("I need file-editing support", "I want a memory plugin", "does anyone have a desktop pet
for this?") and their first job is to decide, quickly, whether the list already covers it
and where to click. Scanning, filtering, and comparing are the primary verbs.

**Secondary — people who do not know dsh yet, plus contributors.** The same page must be
able to explain what dsh is and why this list is worth a star within a few seconds, and must
carry a visible path for someone who built a plugin and wants it listed. The user asked for
these visitors to be attracted too, without displacing the primary job.

## Product Purpose

A curated, community-run index of everything built on dsh: plugins across 11 categories,
core infrastructure, learning guides, and community links. Success means a plugin author
gets found by the developers who need their plugin, and a visitor who has never heard of dsh
leaves understanding what it is.

## Positioning

dsh's own claim is that everything is a plugin — model adapter, tool registry, session log,
permission model, even the agent loop are replaceable, with no privileged core. This list is
the only artifact that inventories that claim at scale: every row states exactly what a
project does *for dsh*, not merely that it exists.

## Operating Context

The site's content is generated from two files in the repo root, `README.md` and
`README.zh.md`. Both are hand-maintained tables (Project / Description / Stars) under `##`
and `###` headings. `site/build.mjs` parses those tables and emits `docs/index.html` and
`docs/zh/index.html`. Every README edit therefore has a site consequence, and the two
languages are edited by hand and can drift. Star counts are snapshots, not live values. A
curation bot and a submission policy (`.github/curator-policy.yml`) govern inbound PRs;
contributing takes one bilingual table row plus a pull request, and entries carry a
`dsh-plugin` GitHub topic.

## Capabilities and Constraints

Confirmed capabilities to preserve:

- Bilingual dual pages at `/` and `/zh/`, mutually linked with `hreflang`, plus a visible
  language switch.
- Content derived from the READMEs by the build; CI rebuilds `docs/` after merge to `main`,
  after the star-history workflow, and on a daily cron, then commits the result with a
  `[skip ci]` message.
- Client-side search across name and description, and category filtering.
- SEO: per-language title/description/keywords, canonical, Open Graph and Twitter tags,
  JSON-LD (`WebSite` + `ItemList` over every entry), `sitemap.xml`, `robots.txt`,
  `.nojekyll`.
- Star and contribution calls to action, plus links to the official repo, the official
  tracker, Discord, Discussions, the `dsh-plugin` topic, X, and Reddit.

Constraints:

- GitHub Pages serves `docs/` from `main`; there is no server runtime and no client
  framework requirement. Output must stay fully static.
- No factual claim may be invented. Prices, users, benchmarks, and capability claims about
  dsh or its plugins do not exist and must not appear.
- Official dsh is a Developer Preview: the official release warns that
  compatibility-breaking changes are coming, so APIs and plugin contracts may change. That
  caveat stays visible.

Brand commitment from the user, binding on this redesign: **the theme is DeepSeek's blue on
white.**

## Evidence on Hand

- `README.md`, `README.zh.md` — the authoritative content, 137 entries in 11 plugin
  categories plus infrastructure, learning, and community sections.
- `assets/star-history/star-history-dark.svg`, `star-history-light.svg`, `.png` — real
  rendered star-history charts, regenerated by `.github/workflows/star-history.yml`.
- Real repository links for every entry, and live GitHub star counts captured in the README
  tables.
- DeepSeek's published brand blue `#4d6bfe` (and its dark-mode variant `#6799fe`).

Not on hand, and therefore not to be fabricated: testimonials, user counts, download
numbers, plugin download or usage statistics, screenshots of any plugin in action, and any
benchmark of dsh itself.

## Product Principles

1. **The list is the interface.** A reader who wants a plugin must reach a decision without
   scrolling past chrome.
2. **Say what it does for dsh.** A row that only says what a project *is* is a wasted row.
3. **Never inflate.** No invented claims, no synthetic statistics presented as real. Honest
   empty space beats fabricated density.
4. **Two languages, one product.** `/` and `/zh/` are the same site, not two sites; neither
   may become a secondary draft of the other.
5. **The README stays canonical.** The site is a view of the repository, not a second
   source of truth that can drift from it.

## Accessibility & Inclusion

Bilingual content must remain legible in Chinese typography, not be styled as an English
layout with Chinese strings dropped in. Light and dark schemes are both published. Keyboard
operation, visible focus, and reduced-motion behaviour are baseline requirements.
